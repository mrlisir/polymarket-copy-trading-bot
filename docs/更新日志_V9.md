## 本版重点

V9 主要围绕 **跟单执行可靠性**、**自动止盈止损（AUTO EXIT）可触发性与可维护性**、**反买/风控与复盘数据一致性**，以及 **关键交易动作的邮件通知（含 dry run 对齐）** 做了补强，实盘与 dry run 保持对齐。

## 修复：跟单失败不应被标记为「已执行」（支持自动重试）

**问题**：单笔与聚合跟单在调用 `postOrder` **之前**就把 Mongo 活动记录的 `botExcutedTime` 置为 `1`，导致下单失败或成交额为 `0` 时，该笔不再进入待执行队列，出现 **跟丢单、无法重试**。

**修复**：

- 仅当 **`executedUsdc > 0`**（认定本笔已实际成交）时，才写入 **`bot: true` + `botExcutedTime: 1`**，并执行原有的 **`touchRecentKey` 去重**（单笔）。
- 成交额为 `0` 时保持 **`botExcutedTime: 0`**，下轮继续拉取并重试；日志前缀 **`[跟单重试]`**。
- **聚合跟单**：删除「整组在下单前统一置 `botExcutedTime: 1`」的逻辑，改为仅在整组成交额大于 0 后为组内每条记录置 `1`。

**涉及文件**：`src/services/tradeExecutor.ts`

## 修复：止盈止损「有仓位却不触发」的常见原因

**问题现象**：部分跟单仓位在 Polymarket 上已有浮盈/浮亏，但程序长期不进入 AUTO EXIT 卖出流程。

**原因与修复**：

1. **Positions API 缺 ROI 字段**  
   部分仓位未返回可用的 `percentPnl` 或 `initialValue/currentValue` 组合，旧逻辑直接 `continue`，永远不触发。  
   **新增** `resolvePercentPnlForProfitExit`（`src/utils/profitExit.ts`）：在 API 主口径缺失时，依次尝试 **`avgPrice + curPrice`**、或 **`currentValue ÷ size` 隐含市价** 推算收益率，与 dry run 中「均价 + 估值价」思路一致。

2. **止盈「目标回收金额」仅用本地 tracked 投入**  
   当 API `initialValue` 大于本地记录的跟单投入时，订单簿预估成交额容易长期低于「以 tracked 为基数」的止盈门槛，表现为 **ROI 已到但反复跳过止盈执行**。  
   **修复**：实盘止盈前计算  
   `basisUsd = max(本地 trackedCostBasisUsd, positions.initialValue)`，  
   再算 `requiredProceeds = basisUsd × (1 + TP%)`。  
   **Dry run**：`basisUsd = max(tracked, size × avgPrice)`，逻辑对齐。

3. **仓位 key 与 Data API 不一致**  
   `makePositionKey` 现对 `asset` 做 **`normalizeClobAssetId`** 再拼接，降低「watch 与 positions 列表对不上」导致永远不监控的概率（V9 延续并明确记入文档）。

**涉及文件**：`src/utils/profitExit.ts`、`src/services/tradeExecutor.ts`、`src/services/dryRunExecutor.ts`

## 新增：手动在 Polymarket 卖光后停止 AUTO EXIT 监控

**问题**：用户在网页端手动平仓后，Data API 已无持仓，但 Mongo 里 **`myBoughtSize` 仍大于 0** 时，旧逻辑会一直保留 AUTO EXIT watch，形成 **空转监控**。

**行为（实盘 + dry run）**：

- 在 watch 上记录 **`positionFlatSince`**：当 **positions（或 dry 模拟仓）中该 `conditionId + asset` 无仓或 size≤0** 时开始计时；一旦有仓则清零。
- 满足：**自 watch 注册起已超过原 grace**，且 **连续无仓时长 ≥ `AUTO_PROFIT_EXIT_FLAT_CLEAR_MS`**（默认 **90000 ms**）时：
  - 删除该 AUTO EXIT watch；
  - 调用 **`clearBuyTrackingForAsset`**（实盘）或等价的 **`myBoughtSize` 清零**（dry run），避免后续卖出/对账仍按旧 tracked 计算。

**新增配置**（已同步 `src/config/env.ts`、`.env.example`、`.env`，并纳入热重载 `applyReloadableProcessEnvToRuntimeEnv`）：

- **`AUTO_PROFIT_EXIT_FLAT_CLEAR_MS`**：默认 `90000`。过短可能在 API 延迟时误清理，请按网络情况调整。

## 增强：自动平仓与熔断、复盘数据一致

**内容摘要**（与跟单核心一致，实盘 / dry run 对称）：

- **`ProfitExitWatch` / `DryProfitExitWatch`** 增加 **`traderAddress`**（来自跟单 BUY 对应交易员）；平仓成功后若有地址则调用 **`handleTraderRiskAfterSell` / `handleDryRiskAfterSell`**，避免 **仅统计跟单卖出、漏计机器人主动止盈止损**。
- **`recordCopyTrackingFill`（AUTO EXIT）**：**`copyMode`** 使用 watch 上的真实模式（反买记为 REVERSE），**`traderAddress` / `traderDisplayName`** 在有地址时使用真实交易员信息。
- **止盈止损复盘盈亏**：优先 **`refAvgPrice`**，否则回退 API **`avgPrice`**，减少与成交价口径严重偏离。
- **watch 清理**：统一经 **`removeProfitExitWatch`**（实盘额外清理 ROI 无法计算时的节流 Map），避免残留键。

## 新增：买入、卖出、止盈、止损、清仓等场景的邮件通知

前提：**`EMAIL_NOTIFY_ENABLED=true`**，且 **`EMAIL_NOTIFY_TO`**、**`EMAIL_SMTP_USER` / `EMAIL_SMTP_PASS`** 等已正确配置（与原有 `notifyOrderSuccess` 一致）。

### 买入 / 卖出

- **实盘**：沿用 `postOrder.ts` 内每笔 FOK **买入 / 卖出** 成功后的 **`notifyOrderSuccess`**（行为与 V8 及以前一致）。
- **Dry Run**：模拟 **买入 / 卖出** 成交后同样调用 **`notifyOrderSuccess`**，并传 **`dryRun: true`**：邮件主题带 **`Dry Run·`**，正文标明 **模拟、未真实下链上/CLOB 单**，与实盘区分。
- **`buildEmailNotifyExtras`** 从 `postOrder.ts` **导出**，供 dry run 与实盘共用 outcome / 跟单模式文案。

### 止盈 / 止损（AUTO EXIT）

- **实盘** `tradeExecutor.ts`：自动止盈或止损在 **`marketSellTokensFOK`** 之后调用 **`notifyAutoProfitExit`**，主题区分 **自动止盈 / 自动止损**；**已基本全平**与**仅部分成交**各发一封（部分成交 `exitFull: false`）。
- **Dry Run**：`maybeAutoProfitExitDryRun` 内对称调用 **`notifyAutoProfitExit`**（`runMode: 'DRYRUN'`）。

### 清仓 / 停跟踪（与「成交通知」并列的独立邮件）

新增 **`notifyPositionClear`**，按场景携带 **`reasonCode`** 与中文说明，便于区分 **Mongo tracked 清零**、**停 AUTO EXIT watch**、**对账平仓** 等：

| reasonCode（摘要） | 典型触发 |
|--------------------|----------|
| `COPY_SELL_TRACKED_CLEARED` | 跟单卖出后 **`myBoughtSize` 按比例清零**（约卖光追踪份额） |
| `AUTO_EXIT_MANUAL_FLAT_MS` | 代理钱包长期无该腿持仓（含手动在 Poly 卖光）超时后清 tracked 并停 watch |
| `AUTO_EXIT_DUST_SIZE` | 持仓低于 `AUTO_PROFIT_EXIT_CLEAR_WHEN_REMAINING_LT_TOKENS` 碎仓清理 |
| `AUTO_EXIT_REDEEMABLE_NO_BID` | AUTO EXIT 触发但无流动性，可赎回/合并路径停跟踪 |
| `AUTO_EXIT_WATCH_STOP_NO_TRACKED` | 无持仓且 tracked 已空，仅停监控 |
| `RECONCILE_FLATTEN` | **仓位对账** CLOB 平仓（有成交或已清 tracked 时通知，避免与「零成交仅拉黑」重复刷屏） |
| `RECONCILE_NO_LIQUIDITY_CLEAR` | 对账时无成交且订单簿不可用，停止后续对账尝试并清 tracked |
| `DRYRUN_AUTO_EXIT_FLAT` / `AUTO_EXIT_WATCH_STOP_NO_TRACKED` / `AUTO_EXIT_REDEEMABLE_NO_BID` | Dry Run 侧与上面对齐的模拟场景 |

**说明**：一次 **跟单卖出** 若同时触发 **卖出成交通知** 与 **清仓（tracked 清零）** 通知，可能连续收到 **两封邮件**（语义不同：成交 vs 追踪状态）。

**涉及文件**：`src/utils/emailNotifier.ts`、`src/utils/postOrder.ts`、`src/services/tradeExecutor.ts`、`src/services/positionReconciliation.ts`、`src/services/dryRunExecutor.ts`

## 其他说明

- **仍可能不自动卖出的情况**：若已触发 TP，但 **`AUTO_PROFIT_EXIT_TAKE_PROFIT_MIN_EXEC_PNL_PCT`** 与 **买盘深度** 要求不满足，程序会保守跳过执行（与「是否识别到价格」不同，属执行层保护）。可调低该阈值或接受滑点风险。
- **Dry run**：与实盘共用上述 AUTO EXIT 规则（flat 清理、成本基准、`resolvePercentPnlForProfitExit` 等），执行层仍为模拟成交；**邮件**上已通过 **`dryRun` / `runMode: DRYRUN`** 与实盘区分。
