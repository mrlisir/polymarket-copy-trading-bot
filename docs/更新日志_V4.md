# 更新日志 V4

更新时间：2026-03-21

---

## 本版重点

V4 主要聚焦三件事：

1. 防止同一市场出现双向新增仓位（同一 `condition` 同时买到两侧）。
2. 增加按交易员的亏损熔断（连续亏损 / 累计亏损触发后自动停跟）。
3. 触发熔断后自动发送邮件提醒，便于第一时间感知风险。

---

## 新增功能 1：双向仓位防抖内存锁（实盘 + Dry Run）

### 背景

原有两头买风控主要依赖持仓数据判断。在高频场景下，如果 Data API 持仓刷新有延迟，可能出现短窗口内两侧 BUY 都通过检查，导致同一市场双向新增仓位。

### 改动

- 在实盘执行器 `src/services/tradeExecutor.ts` 增加了按 `conditionId` 的内存锁：
  - 当某 `condition` 的某一侧 BUY 成功后，写入锁定资产；
  - 在锁有效期内，另一侧 BUY 会被直接跳过（并记录日志）。
- 在模拟执行器 `src/services/dryRunExecutor.ts` 同步实现同样机制。

### 新配置

- `COPY_DOUBLE_SIDE_GUARD_MODE`（已有）
  - `GLOBAL` / `TRADER_ONLY` / `OFF`
- `COPY_DOUBLE_SIDE_GUARD_LOCK_TTL_MS`（新增）
  - 默认：`600000`（10 分钟）
  - 作用：同一 `condition` 买入一侧后，在 TTL 内阻止另一侧 BUY

## 新增功能 2：亏损熔断停跟（实盘 + Dry Run）

### 规则

按“每个交易员地址”独立统计：

- 连续亏损次数达到阈值，或
- 累计亏损金额达到阈值

任一命中后，停止跟单该交易员（当前进程内生效）。

### 统计口径

- 仅在 SELL 成交后按已实现盈亏计算。
- 单笔已实现盈亏 = `卖出成交额 - 卖出代币数量 * 对应持仓均价`
- 盈利会重置“连续亏损次数”；累计亏损为负收益绝对值累加。

### 行为

- 触发后：
  - 该交易员后续待执行交易会被跳过；
  - 为避免队列堆积，对应交易会标记为已处理；
  - 发送邮件告警。

---

## 新增功能 3：熔断邮件提醒

新增风险停跟通知邮件，内容包含：

- 触发时间（北京时间）
- 模式（LIVE / DRYRUN）
- 交易员地址
- 触发原因
- 连续亏损次数
- 累计亏损金额

邮件发送链路与现有通知共用（SMTP + 失败兜底逻辑）。

## 新增配置项（`.env` / `.env.example`）

```env
# 双向仓位防抖内存锁
COPY_DOUBLE_SIDE_GUARD_LOCK_TTL_MS = 600000

# 亏损熔断
COPY_STOP_ON_LOSS_ENABLED = true
COPY_STOP_LOSS_STREAK = 10
COPY_STOP_LOSS_USD = 50
```

说明：

- `COPY_STOP_ON_LOSS_ENABLED=true` 时启用熔断逻辑。
- `COPY_STOP_LOSS_STREAK` 默认 10（连续亏损 N 次停跟）。
- `COPY_STOP_LOSS_USD` 默认 50（累计亏损 N 美金停跟）。

## 补充：临时故障指数退避（可配置）

Mongo / CLOB / 网络抖动时自动重试、不退出进程；退避间隔与 CLOB 初始化次数可通过环境变量调整：

| 变量 | 默认 | 说明 |
|------|------|------|
| `TRANSIENT_RETRY_BASE_MS` | 2000 | 退避基数（毫秒） |
| `TRANSIENT_RETRY_MAX_MS` | 120000 | 单次退避上限（毫秒） |
| `TRANSIENT_BACKOFF_MAX_EXPONENT` | 16 | 指数 cap：`2^min(次数-1, 此项)` |
| `CLOB_INIT_MAX_ATTEMPTS` | 12 | CLOB 客户端初始化最大尝试次数 |
| `TRANSIENT_RESTART_SETTLE_MS` | 2000 | 停止子服务后等待再关库/重连（0=不等待）；优雅关闭前等待亦用此值 |

公式：`delay = min(BASE × 2^min(streak-1, MAX_EXPONENT), MAX_MS)`。

## 注意事项

- 当前“停止跟单”是**进程级熔断**：重启后会重新开始统计。
- 若需要“跨重启持续停跟”，建议下一版增加 Mongo 持久化黑名单。
- 双向仓位内存锁用于弥补 API 刷新延迟窗口，不替代仓位对账机制。
