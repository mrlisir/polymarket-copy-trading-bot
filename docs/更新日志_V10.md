# 更新日志 V10

更新时间：2026-03-25

---

## 本版重点

V10 主要解决 **跟单日志刷屏与误判**、**Data API 持仓缓存导致决策/对账滞后或误判**、**小比例跟单无法达到最小单笔**、**订单计算与限额相关日志误导**，以及 **仓位对账「交易员镜像腿已平」误判导致刚买即卖** 等问题；实盘与 dry run 在涉及逻辑处保持对齐。

---

## 修复：接近结算 / 临近结束时跳过跟买但未标记已处理 → 无限重试刷屏

**问题**：`tradeExecutor` 在「目标仓位已接近结算（`redeemable` / `curPrice`）」等分支里 `continue` 时，**未**将 Mongo 活动 **`botExcutedTime` 置为 `1`**，记录仍被 `readTempTrades` 反复拉取，导致 **`Logger.trade` 大段横幅与资金日志重复刷屏**。

**修复**：在上述跳过路径中 **`updateOne` 标记已处理**（与「跟单重试保留 `botExcutedTime=0`」区分： intentional skip 不应重试）。

**说明**：后续迭代中已 **移除** 仅凭 **`positions.endDate` 早于当前时间** 判定「市场已结束」的分支（见下节），避免与 Polymarket 页面 / 链上成交时间不一致时的误判。

**涉及文件**：`src/services/tradeExecutor.ts`

---

## 修复：仅用 `endDate` 判「市场已结束」不可靠（时区 / API 字段）

**问题**：Data API **`positions.endDate`** 与页面、链上活动 **`timestamp`** 可能不一致；按比例跳过「已过期」会误伤 **仍在交易的 15m 等市场**，并出现「endDate 已过时数百分钟」等不合理日志。

**最终策略**：

- **删除**「`endDate` 已早于现在」即跳过跟单的逻辑。
- **保留** **`COPY_SKIP_FOLLOW_IF_ENDS_WITHIN_MINUTES`**：仅在 **`minutesLeft >= 0`** 且距离结束不足阈值时跳过（避免 `minutesLeft < 0` 时误进「即将结束」分支）。

**涉及文件**：`src/services/tradeExecutor.ts`、`src/services/dryRunExecutor.ts`

---

## 增强：降低跟单决策用的持仓数据滞后（共享 TTL 缓存）

**背景**：`fetchPositionsForUser` 使用 **`DATA_API_POSITIONS_CACHE_TTL_MS`**（默认约 10s），多模块共享，易导致 **`curPrice` / `redeemable` / endDate** 用于跟单时偏旧。

**改动**：

1. **跟单主路径**：`doTrading` / `doAggregatedTrading`、自动止盈读代理持仓等，对关键查询使用 **`fetchPositionsForUserForce`**。
2. **可选后台刷新**：新增 **`POSITIONS_BACKGROUND_REFRESH_INTERVAL_MS`**（**0=关闭**）。大于 0 时，实盘与 dry run 的 executor 内 **`setInterval`** 周期性调用 **`refreshPositionsForCopyWatchers()`**（对 **PROXY_WALLET + 所有交易员** `force` 拉取），与主循环并行（Node 异步 I/O，非 OS 多线程）。

**新增/涉及**：`src/utils/dataApiCache.ts`（`refreshPositionsForCopyWatchers`）、`src/config/env.ts`、`.env.example`、`.env`

---

## 新增：比例算出金额不足最小单笔时可抬升到 `MIN_ORDER_SIZE_USD`

**问题**：`PERCENTAGE` 等小比例下，名义金额常 **低于 `MIN_ORDER_SIZE_USD`（及 CLOB 约 $1）**，跟单被跳过。

**新增配置**：**`COPY_BUMP_SUBMIN_ORDER_TO_MIN=true`** 时，若按比例算出金额 **>0 且 < `MIN_ORDER_SIZE_USD`**，则尝试 **抬升至 `MIN_ORDER_SIZE_USD`**，再受 **`MAX_ORDER_SIZE_USD`、今日剩余 `MAX_DAILY_VOLUME_USD`、余额（99%）、`MAX_POSITION_SIZE_USD`** 约束；抬不上去则仍跳过，并在 **`reason` 中输出「抬升后有效上限」与「最紧约束」**（便于对照 `.env`）。

**涉及文件**：`src/config/copyStrategy.ts`、`src/config/env.ts`（`parseCopyStrategy` 两处）、`.env.example`、`.env`

---

## 修复：`postOrder` 在 `finalAmount===0` 时误报「每日限额即将耗尽」

**问题**：只要 **`orderCalc.finalAmount === 0`** 且存在 **`dailyVolumeStatus`** 且未 `blocked`，就打印 **「每日限额即将耗尽…剩余不足最小交易额」**，即使 **日剩余很大**、真实原因是 **低于最小单笔 / 抬升失败** 等。

**修复**：**仅当** **`dvs.remaining < COPY_STRATEGY_CONFIG.minOrderSizeUSD`** 时再输出该告警。

**涉及文件**：`src/utils/postOrder.ts`

---

## 修复：仓位对账误判「交易员镜像腿已平」→ 刚跟买就被卖

**问题**：**`POSITION_RECONCILE_ON_TRADER_EXIT`** 依赖 Data API 判断交易员在 **镜像 outcome** 上是否仍有仓；**`fetchPositionsForUser` 带 TTL 缓存** 时，交易员刚成交后接口未更新，可能 **短暂显示无仓**，对账 **误平己方仓位**。

**修复**：

1. **`anyTraderStillInMirror`**：拉交易员 positions 时使用 **`fetchPositionsForUser(addr, { force: true })`**。
2. **实盘对账**：拉己方列表使用 **`fetchPositionsForUserForce(PROXY_WALLET)`**。
3. **建仓宽限**：新增 **`POSITION_RECONCILE_TRADER_EXIT_GRACE_MS`**（代码默认 **180000 ms**；可在 `.env` 设为 **60000=1 分钟** 等）。**跟单 BUY 实际成交后** 调用 **`touchReconcileTraderExitGrace`**，宽限期内 **不执行**「交易员已平」触发的对账平仓。  
   **Dry run**：模拟买入成功后同样 **`touchReconcileTraderExitGrace`**；模拟对账分支同样判断 **`isReconcileTraderExitInGrace`**。

**涉及文件**：`src/services/positionReconciliationCore.ts`、`src/services/positionReconciliation.ts`、`src/services/tradeExecutor.ts`、`src/services/dryRunExecutor.ts`、`src/config/env.ts`（含热重载项）、`.env.example`、`.env`

## 配置清单（V10 相关，便于核对）

| 变量 | 说明 |
|------|------|
| `DATA_API_POSITIONS_CACHE_TTL_MS` | 共享 positions 缓存 TTL；跟单关键路径已多用 `force`，可按需调小 |
| `POSITIONS_BACKGROUND_REFRESH_INTERVAL_MS` | 后台强制刷新周期（ms），**0=关** |
| `COPY_BUMP_SUBMIN_ORDER_TO_MIN` | **true** 时尝试将不足最小单笔的比例单抬到 `MIN_ORDER_SIZE_USD` |
| `POSITION_RECONCILE_TRADER_EXIT_GRACE_MS` | 跟买后宽限（ms），**0=关闭**；示例 **60000=1 分钟** |

## 已知与使用建议

1. **`COPY_SKIP_FOLLOW_IF_ENDS_WITHIN_MINUTES`** 仍依赖 **`positions.endDate`**；若该字段不准，可置 **0** 关闭，或结合 **`redeemable` / `curPrice`** 风控使用。
2. **最小单笔与 CLOB**：`postOrder` 内仍有 **约 $1** 等 CLOB 侧约束；**`MIN_ORDER_SIZE_USD` 不得大于 `MAX_ORDER_SIZE_USD`**，否则抬最小逻辑无法成立。
3. **对账**：若完全不希望「跟交易员平仓」自动卖，可设 **`POSITION_RECONCILE_ON_TRADER_EXIT=false`**（**已结算**等路径仍可由 **`POSITION_RECONCILE_ON_RESOLVED`** 控制）。
