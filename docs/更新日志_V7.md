更新时间：2026-03-23

## 本版重点

V7 主要新增 **自动止盈止损平仓与复盘增强**：

- 在 **`npm run dev`（实盘）** 与 **`npm run dryrun`（模拟）** 运行时，持续检测机器人买入后同一仓位的 `percentPnl`；
- 若触发止盈/止损阈值，则 **立即全仓平仓**，并停止再跟踪该仓位（不再持仓/不再依赖后续卖出逻辑计算该仓位的 tracked 买入份额）；
- 触发平仓事件会写入 Mongo 成交流水，并在 `npm run copy-tracking-export` 的 Excel “成交流水”表中展示触发类型、原因和触发 `percentPnl`，方便复盘。

## 新增功能：自动止盈止损（Auto Profit Exit）

### 行为说明

1. 检测粒度
   - 按 `conditionId + asset` 维度聚合监控的仓位。
   - `percentPnl` 来源于机器人持仓计算（仓位端的 `percentPnl` 或估值计算）。

2. 触发规则（满足其一立即触发）
   - 止盈：`percentPnl >= AUTO_PROFIT_EXIT_TAKE_PROFIT_PCT`
   - 止损：`percentPnl <= -AUTO_PROFIT_EXIT_STOP_LOSS_PCT`

3. 平仓与停止跟踪
   - 触发后调用 SELL 路径执行平仓（FOK-like 市价卖出，尽量全额成交）。
   - 若平仓后剩余碎股足够小，则清理该仓位对应的 tracked BUY 追踪，并移除该 watch。

4. 实盘与模拟一致性
   - 实盘：会尝试真实下单卖出。
   - 模拟：不会发送真实交易，但会按订单簿/估值模拟平仓，并同样写入复盘流水字段（用于导出）。

## 日志与复盘增强

### 启动期配置输出（dev/dryrun）

在启动流程中会额外输出自动止盈止损配置摘要，包含：

- 是否启用
- `TP` / `SL`
- 检查间隔（毫秒）
- 失败重试冷却（毫秒）
- 平仓后清理阈值（碎股 token 数）

### 触发时日志与 logs 文件

- 触发前会打印触发类型（take-profit / stop-loss）、当前 `percentPnl`、阈值与仓位摘要。
- 触发后会打印平仓是否完成，以及成交数量/剩余碎股等信息。
- 同时会通过项目的 `Logger` 机制写入 `logs/`（与其它策略日志一致）。

### Excel 复盘导出（copy-tracking-export）

`npm run copy-tracking-export` 的 “成交流水”表新增以下列：

- `自动平仓类型`（`TAKE_PROFIT` / `STOP_LOSS`）
- `自动平仓原因`（触发阈值的原因文案）
- `自动平仓触发Pnl%`（触发时的 `percentPnl`）

并且在成交流水 Mongo 里落地以下字段：

- `autoExitType`
- `autoExitReason`
- `autoExitPercentPnl`

## 新增 / 涉及配置（`.env` / `.env.example`）

你可以在 `.env` / `.env.example` 中配置如下变量（已同步文档默认值）：

```env
AUTO_PROFIT_EXIT_ENABLED = false
AUTO_PROFIT_EXIT_TAKE_PROFIT_PCT = 80
AUTO_PROFIT_EXIT_STOP_LOSS_PCT = 25
AUTO_PROFIT_EXIT_CHECK_INTERVAL_MS = 500
AUTO_PROFIT_EXIT_RETRY_COOLDOWN_MS = 30000
AUTO_PROFIT_EXIT_CLEAR_WHEN_REMAINING_LT_TOKENS = 1.0
```

## 注意事项

- 触发平仓的监控粒度为 `conditionId + asset`。如果你希望按更细粒度（例如具体某笔 `txHash`）停止跟踪，需要在后续进一步调整 watch / 清理逻辑。
- 自动止盈止损会依赖当前持仓计算得到的 `percentPnl`，因此在低流动性或订单簿缺失情况下，平仓估值会受到盘口与价格取值策略影响。

## 本轮补充修复（止盈/止损口径 + 无流动性停止监控 + 下单价格保护）

为解决你反馈的两类问题：

1. **“触发止盈但最终卖出仍亏钱”**：触发口径与实际执行价格存在差异（positions 估值价格 vs orderbook bid 可成交价格/滑点）。
2. **“下单报 invalid price (0.001), min: 0.01”**：orderbook 出现了区间外 price，被直接用于 CLOB 下单导致不可恢复错误。

本轮在核心逻辑中做了如下修复：

### 自动止盈止损触发口径更保守

- `src/services/tradeExecutor.ts` 中的 `maybeAutoProfitExit`：
  - 使用 `orderbook best bid` 推导一个更保守的 `percentPnlFromBid`；
  - 最终触发判断使用 `percentPnlUsed = min(posPercentPnl, bidPercentPnl)`，避免“估值止盈但实际卖出止盈未成立”的误触发。
  - 若出现 `TAKE_PROFIT` 触发但 `realizedPnlUsd < 0`，会额外打出错误日志，帮助快速定位口径偏差。

### 卖出尽量接近全仓退出（多档 bid）

- `src/utils/postOrder.ts` 的 `marketSellTokensFOK`：
  - 不再只取最高 bid 档位，而是按 bid 从高到低逐档尝试卖出，以改善盘口深度不足时的退出质量。
- `src/services/dryRunExecutor.ts` 的 `simulateFillSell` 同步按多档 bid 计算，保持 dryrun/live 更一致。

### CLOB 价格范围保护（避免 invalid price 直接崩）

- `src/utils/postOrder.ts`：
  - 为 BUY / SELL 在下单前增加价格合法性校验，跳过明显不在 CLOB 允许范围（通常要求 `0.01 <= price <= 0.99`）的 orderbook 档位；
  - `marketSellTokensFOK` 中也过滤无效 bid，减少后续触发 runtime 报错的概率。

### 无流动性/过期路径停止后续监控，避免浪费资源

针对 `clob book 404` 或 “订单簿中无买方报价” 等确定性无流动性场景：

- `src/services/positionReconciliation.ts`：
  - 当平仓结果 `soldTokens≈0 && proceedsUsd≈0`（常见于 404/无 bids/过期 redeem 路径）时，记录为 `nonSellablePositionKeys`；
  - 后续在同一进程生命周期内跳过该 `conditionId+asset` 的平仓尝试，并清理 tracked BUY 追踪。
- `src/services/tradeExecutor.ts`：
  - 在自动止盈止损卖出尝试后同样检测 `sold≈0 && proceeds≈0`；
  - 触发“停止跟踪”，清理 tracked BUY，避免 auto-exit 反复尝试对不可卖仓位浪费资源。

### 解决“止盈到了但没有触发卖出”的监控等待问题

- 之前自动止盈/止损在刚注册 watch 后，会等待 `positions API` 反映新买入；
- 若在较短窗口内 `positions API` 仍返回 `size<=0`，旧逻辑会直接丢弃 watch，导致即使后续价格满足阈值也不会再卖出。

本轮修复：

- `src/services/tradeExecutor.ts`：当 positions 尚未反映新买入时，不再丢弃 watch；保留 watch 并让后台线程每 `AUTO_PROFIT_EXIT_CHECK_INTERVAL_MS` 检查一次，直到可计算出 PnL 并触发平仓。
- `src/services/dryRunExecutor.ts`：同步 dryrun：同口径保留 watch 并持续检查（不阻塞主循环）。

## 日志可观测性增强（AUTO EXIT 输出市场标题）

为了便于你在控制台快速定位“哪一个市场”的条目触发/等待/停止跟踪：

- `src/services/tradeExecutor.ts`：
  - `[AUTO EXIT]` 相关日志统一增加 `market=...`（例如 `Solana Up or Down - 5 Minutes`）。
  - 包括：等待 positions 反映、止盈/止损触发、卖出尝试汇总、停止跟踪（清理 tracked BUY）等关键日志。
- `src/services/dryRunExecutor.ts`：
  - `[AUTO EXIT DRYRUN]` 同口径增加 `market=...`，保证模拟/实盘复盘体验一致。
